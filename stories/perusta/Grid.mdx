## Miten sijoittelu merkitään

Leveys annetaan sarakkeina, ei pikseleinä:

```tsx
<Grid>
  <Col base={4} sm={8} md={7}>
    <p className="display-m">Rakennan tuotteita, jotka toimivat…</p>
  </Col>
  <Col base={4} sm={8} md={4} startMd={9}>
    <p className="body-l measure">Suunnittelen käyttöliittymät…</p>
  </Col>
</Grid>
```

CSS:ssä tämä on kolme sääntöä, ei enempää:

```css
.grid {
  display: grid;
  grid-template-columns: repeat(var(--columns), minmax(0, 1fr));
  column-gap: var(--gutter);
}
.col { grid-column: span var(--span-base) / span var(--span-base); }
@media (min-width: 900px) { .col { grid-column: var(--start-md, auto) / span var(--span-md); } }
```

<div className="doc-callout">
  <strong>Miksi tämä eikä kiinteät pikselisarakkeet.</strong> Sivupohjat oli alun perin
  ladottu käsin arvoilla kuten <code>60px minmax(0,1fr) 360px</code>. Ne näyttävät
  oikealta yhdessä leveydessä ja hajoavat kaikissa muissa — eikä 600–1200 px:n välille
  jäävää aluetta kattanut yksikään sivupohja. Tokeneista luettu grid kattaa ne kaikki.
</div>

## Täysleveä kaista

Listarivit ja käännetyt palkit ulottuvat reunaan, mutta niiden sisältö pysyy samassa
linjassa muun sivun kanssa. Se hoidetaan yhdellä utilitylla:

```css
.bleed {
  width: 100%;
  padding-inline: max(
    var(--page-padding),
    calc((100% - var(--max-width)) / 2 + var(--page-padding))
  );
}
```

Komponentti ei siis maalaa omaa sivupaddingiaan — muuten se tulisi kahdesti
`.page`-käärön sisällä.
